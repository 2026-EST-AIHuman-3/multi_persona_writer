# Novelist Persona Fine-tuning

> Persona Writer Studio의 소설 작가 페르소나를 구현하기 위한  
> Qwen3-8B 기반 LoRA 파인튜닝 프로젝트입니다.

---

## 1. 담당 파트 소개

Persona Writer Studio는 소설가, 영화 시나리오 작가, 게임 시나리오 작가, 광고 카피라이터 등 다양한 작가 페르소나를 전환하며 창작할 수 있는 AI 서비스입니다.

팀원들은 각자 하나의 작가 페르소나를 맡아 LoRA 파인튜닝을 진행했습니다. 저는 그중 **감정과 분위기 중심의 한국어 소설을 생성하는 소설 작가 페르소나**를 담당했습니다.

소설 데이터셋 구축과 전처리부터 QLoRA·LoRA 학습, 결과 평가, 추론 테스트까지 소설 작가 모델의 파인튜닝 전 과정을 수행했습니다.

초기에는 제한된 GPU 메모리에서도 학습할 수 있도록 4-bit NF4 QLoRA 방식을 적용했습니다. 이후 출력 품질과 안정성을 비교하기 위해 bf16 LoRA 학습을 추가로 진행했으며, 최종적으로 **Qwen3-8B 모델을 bf16으로 로드하고 LoRA adapter만 학습하는 방식**을 사용했습니다.

완성된 소설 작가 LoRA adapter는 팀의 서비스 통합 과정에서 멀티 페르소나 기능에 활용되었습니다.

## 2. 담당 업무

- 소설 작가 페르소나의 문체 및 출력 형식 설계
- 학습용 소설 데이터 생성·수정 및 품질 검수
- 데이터셋 train/validation/test 분할
- 프롬프트와 답변의 평균 토큰 길이 분석
- Qwen3-8B 기반 4-bit NF4 QLoRA 학습
- Qwen3-8B 기반 bf16 LoRA 학습 및 결과 비교
- 학습된 LoRA adapter 추론 테스트
- 출력 결과 평가 및 프롬프트 개선

## 3. 개발 목표

### ① 소설 작가 문체 구현

사용자의 요청을 바탕으로 단순한 문장을 생성하는 것이 아니라, 인물의 감정과 장면의 분위기가 자연스럽게 드러나는 한국어 소설 문체를 구현하는 것을 목표로 했습니다.

### ② 페르소나 일관성 유지

소설 작가 페르소나 선택 시 다른 작가 페르소나와 구분되는 문체를 유지하고, 다음과 같은 형식으로 일관된 결과를 생성하도록 설계했습니다.

- `[소설 장면]`: 감정·배경·감각 묘사가 포함된 소설 본문
- `[작가 코멘트]`: 생성된 장면에 대한 짧고 부드러운 설명

### ③ 한국어 출력 안정성 개선

한국어 문장에 중국어, 한자, 키릴 문자 등 의도하지 않은 문자가 섞이거나 문체가 흔들리는 문제를 줄이고, 자연스러운 한국어 창작 결과를 생성하는 것을 목표로 했습니다.

### ④ 소설 작가 LoRA adapter 제작

전체 모델을 다시 학습하지 않고 소설 작가의 문체적 특징을 학습하는 LoRA 방식을 활용했습니다. 학습 결과를 추론 테스트로 검증하고, 전체 서비스에서 활용할 수 있는 소설 작가 LoRA adapter를 제작하는 것을 목표로 했습니다.

## 4. 데이터셋 구축 및 통계

### 데이터셋 구성

소설 작가 페르소나가 일관된 한국어 문체를 학습할 수 있도록 총 101개의 데이터를 구축했습니다.

| 데이터 구분 | 개수 | 용도 |
|---|---:|---|
| 생성 데이터 | 65개 | 모델 학습에 사용할 소설 장면 |
| 수정 데이터 | 16개 | 품질 기준에 맞게 직접 수정한 학습 데이터 |
| Validation 데이터 | 10개 | 학습 과정의 성능 검증 |
| Test 데이터 | 10개 | 학습 완료 후 결과 평가 |
| **합계** | **101개** |  |

최종적으로 학습 데이터 81개, 검증 데이터 10개, 테스트 데이터 10개로 분리했습니다.

학습 데이터는 특정 장르의 형식을 학습하는 것보다 다양한 요청에서도 동일한 문체적 특징을 유지할 수 있도록 다음 세 가지 범주로 구성했습니다.

| 데이터 범주 | 개수 | 주요 표현 |
|---|---:|---|
| 일상·감정 | 29개 | 인물의 감정 변화와 일상적인 관계 |
| 공포·긴장 | 27개 | 불안감, 긴장감, 제한된 정보 표현 |
| 판타지·SF | 25개 | 비현실적 배경과 세계관 묘사 |
| **합계** | **81개** |  |

### 데이터 형식

데이터는 한 줄에 하나의 JSON 객체를 저장하는 JSONL 형식으로 구성했습니다.

```json
{
  "instruction": "가을 저녁, 오래된 카페 창가에 앉아 혼자 시간을 보내는 장면을 따뜻하고 아련한 분위기로 서술해 줘.",
  "output": "[소설 장면]\n\n카페 창문 너머로 붉게 물든 가을 하늘이...\n\n[작가 코멘트]\n\n가을 특유의 따뜻하면서도 쓸쓸한 분위기가 느껴지도록 공간과 계절 묘사를 중심으로 전개해봤어요."
}
```
- `instruction`: 장면, 분위기, 인물 또는 상황을 지정하는 사용자 요청
- `output`: `[소설 장면]`과 `[작가 코멘트]`로 구성된 소설 작가의 응답

### 출력 형식 설계

소설 작가 페르소나가 본문만 생성하는 것에서 끝나지 않고, 창작 의도까지 전달하도록 학습 데이터의 출력 형식을 두 부분으로 구성했습니다.

`[소설 장면]`
- 사용자가 요청한 상황과 분위기를 반영한 소설 본문
- 인물의 행동과 감정 변화 표현
- 배경과 감각적인 요소를 활용한 장면 묘사
- 자연스러운 대사와 서술형 문체 사용

`[작가 코멘트]`
- 장면에서 중점적으로 표현한 요소 설명
- 창작 방향과 묘사 의도를 짧게 전달
- 딱딱한 설명 대신 부드러운 존댓말 사용
- 본문의 분위기를 해치지 않도록 간결하게 작성

학습 코드에서는 각 데이터의 `output` 전체를 assistant 응답으로 변환했습니다. 
따라서 모델은 소설 문체뿐만 아니라 `[소설 장면]`과 `[작가 코멘트]`의 출력 구조, 작가 코멘트의 말투까지 함께 학습했습니다.

서비스 추론 시에도 동일한 출력 규칙을 프롬프트에 명시하여, 파인튜닝으로 학습한 형식이 안정적으로 유지되도록 했습니다.

### 데이터 구성 관련 의사결정

초기 데이터는 `[소설 장면]`과 `[작가 코멘트]`가 함께 포함된 형태로 구성했습니다. 학습 대상을 소설 본문에 집중시키기 위해 작가 코멘트를 제외하는 방안도 검토했습니다.

하지만 제한된 프로젝트 일정에서 데이터 수정과 재검수에 시간을 사용하기보다, 기존 데이터 구조를 유지한 상태에서 추가 파인튜닝을 진행하고 결과를 비교하는 것이 더 효과적이라고 판단했습니다.

따라서 최종 학습에서는 `[소설 장면]`과 `[작가 코멘트]`를 모두 포함했으며, 모델이 감정과 분위기 중심의 소설 문체뿐 아니라 고정된 출력 구조와 작가 코멘트의 부드러운 말투까지 함께 학습하도록 구성했습니다.

### 문체 품질 기준

데이터마다 표현 방식이 달라져 페르소나의 문체가 흔들리지 않도록 공통 스타일 가이드를 적용했습니다.

- 자연스러운 한국어 서술형 문체 사용
- 인물의 행동과 감정 변화를 장면 속에서 표현
- 계절, 공간, 소리, 향기 등 감각적인 배경 묘사 포함
- 단순한 설명 나열과 반복 표현 최소화
- 대사는 지나치게 은유적으로 작성하지 않도록 조정
- 은어, 이모지 및 불필요한 외래 문자 사용 제외
- `[소설 장면]`과 `[작가 코멘트]` 형식 유지
- 작가 코멘트는 창작 의도를 짧고 부드러운 존댓말로 설명

### 데이터 전처리 및 분석

`data_split.py`를 사용해 전체 데이터를 train, validation, test 데이터로 분리했습니다.

또한 `calculate_dataset_stats.py`를 통해 프롬프트와 답변의 평균 토큰 길이를 계산하고, 분석 결과를 바탕으로 학습 시 사용할 최대 시퀀스 길이를 검토했습니다.

## 5. QLoRA·bf16 LoRA 학습

### Base Model

최종 Base model은 `Qwen/Qwen3-8B`를 사용했습니다.

초기에는 한국어 생성 품질을 고려해 EXAONE 3.5를 검토했지만, 원격 모델 코드와 Transformers 간의 호환성 문제로 인해 LoRA 학습 환경을 안정적으로 구성할 수 있는 Qwen3-8B로 변경했습니다.

> 자세한 모델 변경 과정은 [트러블슈팅](#9-트러블슈팅)에서 확인할 수 있습니다.

Qwen3-8B의 기본 언어 생성 능력을 유지하면서 소설 데이터의 문체와 출력 형식을 추가로 학습하기 위해, 전체 파라미터가 아닌 일부 adapter만 학습하는 LoRA 방식을 적용했습니다.

### 1. 4-bit NF4 QLoRA 학습

초기에는 GPU 메모리 사용량을 줄이기 위해 4-bit NF4 QLoRA 방식으로 학습을 진행했습니다.

```python
bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_compute_dtype=torch.bfloat16,
    bnb_4bit_use_double_quant=True
)
```
QLoRA는 기반 모델의 가중치를 4-bit로 양자화하여 로드하고, LoRA adapter만 학습하는 방식입니다. 
이를 통해 8B 규모의 모델도 제한된 GPU 환경에서 비교적 적은 메모리로 학습할 수 있었습니다.

주요 적용 설정은 다음과 같습니다.

- BitsAndBytesConfig를 사용한 4-bit 양자화
- NF4 양자화 방식 적용
- 연산 자료형으로 bfloat16 사용
- quantization_config=bnb_config 적용
- paged_adamw_8bit optimizer 사용

### 2. bf16 LoRA 학습

QLoRA 학습 이후 양자화 여부에 따른 출력 차이와 안정성을 확인하기 위해 bf16 LoRA 학습을 추가로 진행했습니다.

bf16 LoRA에서는 4-bit 양자화를 적용하지 않고, Qwen3-8B 기반 모델을 torch.bfloat16 자료형으로 로드했습니다. 기반 모델의 전체 가중치는 고정하고 LoRA adapter만 학습했습니다.

```Python
model = AutoModelForCausalLM.from_pretrained(
    model_name,
    torch_dtype=torch.bfloat16,
    device_map="auto"
)
```

주요 변경 사항은 다음과 같습니다.
| 구분        | QLoRA              | bf16 LoRA       |
| --------- | ------------------ | --------------- |
| 기반 모델 로드  | 4-bit NF4          | bfloat16        |
| 양자화 설정    | 적용                 | 미적용             |
| 학습 대상     | LoRA adapter       | LoRA adapter    |
| Optimizer | `paged_adamw_8bit` | `adamw_torch`   |
| 특징        | GPU 메모리 절약         | 양자화 없는 학습 결과 비교 |

### 최종 학습 방식
QLoRA와 bf16 LoRA의 출력을 비교한 후, 최종적으로 Qwen3-8B 모델을 bf16으로 로드하고 LoRA adapter만 학습하는 방식을 선택했습니다.

| 설정                          | 최종값             |
| --------------------------- | --------------- |
| Base model                  | `Qwen/Qwen3-8B` |
| Fine-tuning                 | bf16 LoRA       |
| Epochs                      | 2               |
| Learning rate               | `5e-5`          |
| Batch size                  | 1               |
| Gradient accumulation steps | 8               |
| Optimizer                   | `adamw_torch`   |

작은 batch size를 사용하면서도 gradient accumulation을 8회 적용하여 여러 학습 단계의 gradient를 누적한 뒤 한 번에 가중치를 업데이트하도록 구성했습니다.

## 6. 학습 버전별 결과 비교

### 테스트 방법

각 모델의 출력 차이를 비교하기 위해 동일한 테스트 프롬프트를 사용했습니다.

테스트는 다음 네 가지 유형으로 구성했습니다.

1. 감정 중심 장면 생성
2. 판타지·몽환적 장면 생성
3. 공포·긴장 장면 생성
4. 기존 장면의 분위기 수정

출력 결과는 다음 기준으로 비교했습니다.

- `[소설 장면]`과 `[작가 코멘트]` 형식 유지
- 자연스러운 한국어 문체
- 요청한 감정과 분위기 반영
- 장면의 문맥과 설정 유지
- 수정 요청에 대한 원문 보존
- 중국어 등 불필요한 외래 문자 혼입 여부

### 모델별 결과

> 아래 결과는 파인튜닝 직후, 최종 추론 프롬프트를 적용하기 전에 진행한 테스트입니다. 프롬프트의 영향을 최소화하고 각 LoRA 버전의 학습 효과를 비교하기 위해 동일한 입력과 생성 조건을 사용했습니다.

| 모델 | 결과 | 판단 |
|---|---|---|
| Base Qwen3-8B | 출력 형식은 프롬프트로 유지할 수 있었지만, 한국어 문체가 부자연스럽고 작가 코멘트가 분석문처럼 생성됨 | 파인튜닝 필요 |
| QLoRA v1 | 출력 형식과 작가 코멘트의 말투가 개선되고 학습 효과가 뚜렷하게 나타남 | 중국어 및 학습 데이터 표현 혼입으로 과적합 우려 |
| QLoRA v2 | 중국어와 특정 표현의 과도한 혼입은 감소함 | 학습 효과가 약해지면서 기본 모델의 어색한 한국어 문체가 다시 나타남 |
| bf16 LoRA | 중국어 혼입이 감소하고 장면 유지력과 수정 요청의 안정성이 개선됨 | 일부 어색한 표현은 추론 프롬프트로 추가 보완 필요 |

### 주요 문제 사례

#### QLoRA v1: 외래 문자 혼입

```text
“好久不见.”
```
한국어 소설 장면에 중국어 대사가 포함되는 문제가 나타났습니다.

#### QLoRA v1: 수정 요청의 문맥 이탈

```text
세탁기 사이에서 작은 틈이 생겨 있었다.
```
원문의 분위기를 수정해달라는 요청에서 기존 장면과 관련성이 낮은 설정이 새롭게 추가되었습니다.

#### QLoRA v2: 부자연스러운 한국어 표현

```text
아무런 소리도 없었지만, 그 소리가 있는 듯한 느낌이었다.
```
과도한 표현 혼입은 감소했지만 기본 모델의 어색한 문장 구조가 일부 남았습니다.

#### bf16 LoRA: 남아 있는 문법적 어색함

```text
비가 점점 세워지면서
```
중국어 혼입과 장면 이탈은 줄었지만 일부 문법적으로 어색한 표현이 남았습니다.

#### 최종 모델 선정
QLoRA v1은 학습 효과가 강했지만 중국어와 특정 데이터 표현이 출력에 섞이는 문제가 있었습니다. QLoRA v2에서는 이러한 현상이 감소했으나, 학습 효과도 함께 약해져 기본 모델의 부자연스러운 한국어 문체가 다시 나타났습니다.

bf16 LoRA는 QLoRA에 비해 중국어 혼입이 감소했으며, 사용자가 요청한 장면과 기존 원문의 맥락을 비교적 안정적으로 유지했습니다. 이에 따라 Qwen3-8B 기반 bf16 LoRA를 최종 학습 방식으로 선택했습니다.

파인튜닝만으로 완전히 해결되지 않은 문법적 어색함과 작가 코멘트의 말투는 최종 서비스의 추론 프롬프트를 보완하여 개선했습니다.

## 7. 프롬프트 엔지니어링 

### 개선 배경

bf16 LoRA는 QLoRA보다 중국어 혼입과 장면 이탈이 줄었지만, 파인튜닝 직후 테스트에서는 다음과 같은 문제가 일부 남았습니다.

- 문법적으로 어색하거나 번역체처럼 보이는 한국어 표현
- 사용자 요청에 없는 공포 요소와 새로운 사건 추가
- 수정 요청에서 원문의 설정과 무관한 내용 생성
- 작가 코멘트가 딱딱한 분석문 형태로 출력
- 장면이 지나치게 짧거나 감정이 직접적으로 설명되는 문제

파인튜닝으로 소설 작가의 기본 문체와 출력 형식을 학습하고, 추론 프롬프트를 통해 언어·장면·수정 범위·작가 코멘트에 관한 세부 규칙을 보완했습니다.

### 문제별 프롬프트 개선

| 파인튜닝 직후 문제 | 추가한 프롬프트 규칙 | 목적 |
|---|---|---|
| 중국어와 외래 문자 혼입 | 한국어만 사용하고 중국어·영어·일본어·한자를 사용하지 않도록 제한 | 한국어 출력 일관성 유지 |
| 번역체와 과도한 비유 | 자연스러운 한국어 문체와 과한 비유 금지 | 문장 가독성과 자연스러움 개선 |
| 관련 없는 공포 요소 추가 | 요청하지 않은 귀신·괴물·죽음·저주 등을 추가하지 않도록 제한 | 사용자가 지정한 분위기 유지 |
| 기본 분위기가 공포로 변함 | 분위기가 없으면 잔잔하고 서정적인 일상 분위기 적용 | 학습 데이터의 공포 표현이 다른 요청에 영향을 주는 현상 방지 |
| 수정 요청에서 원문 이탈 | 원문의 장르·장소·인물·사건을 유지하고 분위기와 문체만 변경 | 원문 보존과 수정 안정성 향상 |
| 장면이 지나치게 짧음 | 소설 장면을 5~8문장으로 작성하고 감정·분위기 묘사 포함 | 장면의 완성도와 충분한 분량 확보 |
| 감정을 직접 설명함 | 행동·공간·빛·소리·감각으로 감정을 표현 | 소설다운 간접적 감정 묘사 강화 |
| 작가 코멘트가 분석문처럼 출력 | 한 문장의 부드러운 존댓말과 지정된 종결 표현 사용 | 소설 작가 페르소나의 말투 일관성 유지 |

## 8. 최종 평가와 출력 결과

### 평가 방법

파인튜닝과 프롬프트가 출력 품질에 미치는 영향을 분리하여 확인하기 위해 다음 네 가지 조합을 비교했습니다.

1. Base 모델 + 약한 프롬프트
2. Base 모델 + 강한 프롬프트
3. Fine-tuned 모델 + 약한 프롬프트
4. Fine-tuned 모델 + 강한 프롬프트

각 결과는 유용성, 스타일 준수도, 응답 길이, 추론 속도를 기준으로 5점 척도로 평가했습니다.

| 모델과 프롬프트 | 유용성 | 스타일 준수도 | 응답 길이 | 추론 속도 | 종합 평점 |
|---|---:|---:|---:|---:|---:|
| Base + 약한 프롬프트 | 3.5 | 2.9 | 5.0 | 3.0 | 3.60 |
| **Base + 강한 프롬프트** | 4.0 | **4.2** | 4.0 | **5.0** | **4.30** |
| Fine-tuned + 약한 프롬프트 | 3.5 | 2.9 | 5.0 | 2.0 | 3.35 |
| Fine-tuned + 강한 프롬프트 | **4.5** | 4.0 | 4.0 | 4.0 | **4.13** |

> 본 평가는 제한된 테스트 프롬프트를 대상으로 진행한 팀 내부 정성평가이며, 절대적인 성능 지표가 아니라 모델과 프롬프트 조합 간의 상대적 비교를 목적으로 합니다.

### 테스트 생성 조건

모델 버전별 출력을 동일한 조건에서 비교하기 위해 확률 샘플링을 비활성화하고 `do_sample=False`를 적용했습니다.

초기에는 기존에 사용하던 `temperature`, `top_p`, `top_k` 설정이 남아 있어 해당 값이 무시된다는 경고가 발생했습니다. 비교 모드에서는 사용되지 않는 샘플링 파라미터를 제거하여 생성 조건을 명확하게 통일했습니다.

### Fine-tuned 모델 + 최종 프롬프트 출력

```text
[소설 장면]

거대한 인공 태양이 천장을 붉게 물들였다가 점점 희미해졌다.
도시는 그 빛을 따라 조용히 숨죽이며 움직였다.
거리를 걷는 사람들의 발걸음이 소란을 일으키지 않는 듯했다.
창가에 몸을 기댄 여자는 마지막 빛을 바라보고 있었다.
눈앞에 스며드는 빛의 흐름 속에서 그녀는 자신도 모르게 미소 지었다.

[작가 코멘트]

마치 시간이 멈춘 듯한 순간을 통해 고요함 속에 숨은 우울감과
상실감을 전달해봤어요.
```
최종 프롬프트를 적용하자 불필요한 사건이나 공포 요소가 추가되지 않았으며, 지정한 출력 형식과 부드러운 작가 코멘트 말투도 안정적으로 유지되었습니다.

### 평가 결과 분석

예상과 달리 종합 평점은 **Base 모델 + 강한 프롬프트가 4.30점으로 가장 높았습니다.** Fine-tuned 모델 + 강한 프롬프트는 유용성에서 가장 높은 4.5점을 기록했지만, 스타일 준수도와 추론 속도를 포함한 종합 평가에서는 4.13점으로 두 번째였습니다.

두 모델 모두 강한 프롬프트를 적용했을 때 점수가 크게 상승했습니다. 이를 통해 이번 소설 생성 과제에서는 파인튜닝 여부뿐 아니라, 출력 형식과 문체·언어·문맥 유지 규칙을 구체적으로 정의한 프롬프트가 결과 품질에 큰 영향을 준다는 점을 확인했습니다.

종합 평점에서는 Base 모델이 가장 높았지만, 본 프로젝트는 페르소나별 LoRA adapter를 전환하는 서비스를 목표로 했으며 Fine-tuned 모델은 창작 결과의 유용성에서 가장 높은 점수를 기록했습니다. 이에 따라 소설 작가의 문체와 출력 구조를 학습한 Fine-tuned 모델을 최종 서비스에 적용했습니다.

다만 101개의 비교적 작은 데이터셋만으로는 Base 모델의 일반적인 한국어 생성 능력을 안정적으로 넘어서는 데 한계가 있었습니다. 이번 결과를 통해 제한된 데이터 환경에서는 LoRA 적용 자체보다 데이터 품질과 프롬프트 설계가 더 큰 영향을 줄 수 있다는 점을 확인했습니다. 향후에는 데이터의 양과 표현 다양성을 확대하고 반복적이거나 어색한 표현을 추가로 정제할 필요가 있습니다.

## 9. 트러블슈팅

### 1. EXAONE 3.5 호환성 문제로 Base model 변경

#### 문제

하지만 기존 원격 PC 환경에서 모델을 로드하고 답변을 생성하는 과정에서 오류가 발생했습니다.

| 항목 | 기존 환경 |
|---|---|
| OS | Ubuntu 20.04 |
| Python | 3.8.10 |
| Transformers | 4.46.3 |
| GPU | NVIDIA A100 |

모델 로딩 시 다음 오류가 발생했습니다.

```text
ImportError: cannot import name 'RopeParameters'
```

#### 원인

EXAONE은 trust_remote_code=True를 통해 Hugging Face에 저장된 전용 모델 코드를 불러옵니다.

EXAONE의 원격 모델 코드는 Transformers 내부의 RopeParameters를 사용하지만, 기존에 설치된 Transformers 4.46.3에는 해당 기능이 존재하지 않았습니다.

또한 Python 3.8에서는 필요한 최신 Transformers 버전을 설치할 수 없었습니다.

```text
Python 3.8
→ 최신 Transformers 설치 불가
→ EXAONE 원격 모델 코드와 호환 실패
```

#### 해결 시도
Miniconda를 설치하고 Python 3.10 기반의 별도 환경을 구성한 뒤 여러 Transformers 버전을 테스트했습니다.

| Transformers | 결과                      |
| ------------ | ----------------------- |
| 4.46.3       | `RopeParameters` 오류     |
| 4.51.0       | 모델 로딩 실패                |
| 4.56.2       | `RopeParameters` 오류     |
| 4.57.3       | `RopeParameters` 오류     |
| 5.9.0        | 모델 로딩 성공, 생성 단계에서 오류 발생 |

Transformers 5.9.0에서는 모델 로딩에 성공했지만, model.generate() 실행 시 다음 오류가 발생했습니다.

```bash
TypeError: create_causal_mask() got an unexpected keyword argument 'input_embeds'
```

pipeline("text-generation") 방식도 내부적으로 generate()를 호출하기 때문에 동일하게 실패했습니다.

이를 통해 단순한 설치 문제가 아니라, EXAONE 원격 모델 코드와 Transformers 내부 API 사이의 버전 호환성 문제임을 확인했습니다.

#### 최종 결정
프로젝트 일정 안에 EXAONE과 호환되는 버전을 추가로 탐색하고 LoRA 학습 가능 여부까지 검증하는 것은 위험이 크다고 판단했습니다.

따라서 다음 조건을 고려해 Base model을 `Qwen/Qwen3-8B`로 변경했습니다.

- Transformers에서 공식적으로 지원되는 모델 구조
- PEFT·TRL 기반 LoRA 학습 사례와 자료가 많음
- 기존 환경보다 안정적인 학습 환경 구성 가능
- 프로젝트 일정 내 학습 및 결과 비교 가능

#### 결과
Python 3.10과 Transformers 4.51.3 기반의 별도 환경을 구성하고, Qwen3-8B를 사용해 QLoRA 및 bf16 LoRA 학습을 완료했습니다.

이번 경험을 통해 모델의 기본 출력 품질뿐 아니라 라이브러리 호환성, 재현 가능성, 학습 사례 및 프로젝트 일정까지 함께 고려해 모델을 선정해야 한다는 점을 확인했습니다.


### 2. QLoRA 과적합과 학습 효과 저하 개선

#### 문제

초기에는 GPU 메모리 사용량을 줄이기 위해 Qwen3-8B를 4-bit NF4로 로드하고, LoRA adapter만 학습하는 QLoRA 방식을 사용했습니다.

QLoRA v1은 출력 형식과 소설 문체를 강하게 학습했지만, 테스트 과정에서 중국어와 학습 데이터의 특정 표현이 출력에 섞이는 문제가 나타났습니다.

```text
“好久不见.”
```
또한 기존 장면의 분위기만 수정해달라는 요청에서 원문과 관련성이 낮은 설정이 추가되기도 했습니다.

```text
세탁기 사이에서 작은 틈이 생겨 있었다.
```
총 101개의 데이터 중 실제 train 데이터는 81개였기 때문에, 강한 학습 설정으로 특정 표현을 과도하게 학습했을 가능성이 있다고 판단했습니다.

#### v1과 v2 설정 비교
과적합 경향을 줄이기 위해 v2에서는 LoRA adapter의 크기와 학습 강도를 함께 낮췄습니다.

| 설정                    |           QLoRA v1 |           QLoRA v2 | 변경 목적             |
| --------------------- | -----------------: | -----------------: | ----------------- |
| LoRA rank             |                 16 |                  8 | 학습 파라미터 수 축소      |
| LoRA alpha            |                 32 |                 16 | adapter의 반영 강도 감소 |
| LoRA dropout          |               0.05 |                0.1 | 과적합 완화            |
| Epochs                |                  3 |                  1 | 반복 학습 감소          |
| Learning rate         |             `2e-4` |             `5e-5` | 가중치 변화 폭 감소       |
| Target modules        |    Attention + MLP |     Attention only | 학습 범위 축소          |
| Optimizer             | `paged_adamw_8bit` | `paged_adamw_8bit` | 동일                |
| Batch size            |                  1 |                  1 | 동일                |
| Gradient accumulation |                  8 |                  8 | 동일                |

v1에서는 Attention 영역뿐 아니라 MLP 영역까지 학습했습니다.

```Python
target_modules=[
    "q_proj",
    "k_proj",
    "v_proj",
    "o_proj",
    "gate_proj",
    "up_proj",
    "down_proj",
]
```

v2에서는 학습 범위를 Attention 영역으로 제한했습니다.

```Python
target_modules=[
    "q_proj",
    "k_proj",
    "v_proj",
    "o_proj",
]
```
> QLoRA 설정의 bf16=True는 학습 연산에 bfloat16을 사용한다는 의미이며,
> Base model의 가중치는 4-bit NF4로 양자화된 상태입니다.

#### QLoRA v2 결과
v2에서는 중국어와 특정 학습 표현이 직접적으로 섞이는 현상이 감소했습니다.

하지만 LoRA rank, 학습률, epoch 및 target module을 동시에 줄이면서 학습 효과도 상대적으로 약해졌습니다. 그 결과 Base model의 부자연스러운 한국어 문체가 다시 나타났습니다.

```text
그것은 아니라.
```
```text
아무런 소리도 없었지만, 그 소리가 있는 듯한 느낌이었다.
```
| 버전       | 결과                                  |
| -------- | ----------------------------------- |
| QLoRA v1 | 학습 효과는 강하지만 외국어·특정 표현 혼입과 과적합 경향 발생 |
| QLoRA v2 | 혼입 현상은 감소했지만 소설 문체에 대한 학습 효과도 약해짐   |

#### bf16 LoRA 전환
QLoRA의 학습 강도만 다시 조정하기보다, 4-bit 양자화를 적용하지 않는 bf16 LoRA 방식과 결과를 비교하기로 했습니다.

bf16 LoRA에서는 v2의 안정적인 LoRA 설정을 유지하면서 epoch를 2회로 늘려, v1과 v2 사이의 학습 강도를 적용했습니다.

| 설정                    |                           최종 bf16 LoRA |
| --------------------- | -------------------------------------: |
| Base model dtype      |                       `torch.bfloat16` |
| 4-bit 양자화             |                                    미적용 |
| LoRA rank             |                                      8 |
| LoRA alpha            |                                     16 |
| LoRA dropout          |                                    0.1 |
| Epochs                |                                      2 |
| Learning rate         |                                 `5e-5` |
| Batch size            |                                      1 |
| Gradient accumulation |                                      8 |
| Optimizer             |                          `adamw_torch` |
| Target modules        | `q_proj`, `k_proj`, `v_proj`, `o_proj` |

#### 결과
bf16 LoRA에서는 QLoRA v1에서 나타났던 중국어 혼입이 감소했으며, 사용자가 지정한 장면과 기존 원문의 맥락을 비교적 안정적으로 유지했습니다.

| 방식        | 주요 결과                           |
| --------- | ------------------------------- |
| QLoRA v1  | 강한 학습 효과, 외국어·특정 표현 혼입          |
| QLoRA v2  | 혼입 감소, 학습 효과 부족                 |
| bf16 LoRA | 중국어 혼입 감소, 장면 유지력과 수정 요청 안정성 개선 |

이에 따라 최종 파인튜닝 방식으로 Qwen3-8B 기반 bf16 LoRA를 선택했습니다.

다만 bf16 LoRA에서도 일부 문법적으로 어색한 표현은 남아 있었습니다.
```text
비가 점점 세워지면서
```
남아 있는 한국어 문체와 장면 이탈 문제는 최종 추론 프롬프트에 언어, 문체, 수정 범위 및 금지 요소에 관한 규칙을 추가해 보완했습니다.

#### 배운 점

학습 효과가 강하다고 해서 반드시 좋은 출력으로 이어지는 것은 아니며, 데이터가 적을수록 학습 범위와 강도를 세밀하게 조절해야 한다는 점을 확인했습니다.

또한 v2에서는 여러 하이퍼파라미터를 동시에 변경했기 때문에 각 설정의 영향을 개별적으로 측정하기 어려웠습니다. 향후에는 한 번에 하나의 설정만 변경하는 방식으로 실험해 각 하이퍼파라미터의 영향을 명확하게 비교할 필요가 있습니다.

## 10. 한계 및 회고

### 한계

#### 1. 제한된 데이터 규모

전체 데이터는 101개이며, 실제 학습에 사용한 데이터는 81개였습니다. 소설 작가의 문체를 안정적으로 학습하고 다양한 사용자 요청에 대응하기에는 데이터의 양과 표현 범위가 제한적이었습니다.

QLoRA v1에서는 특정 표현과 외국어가 출력에 섞이는 과적합 경향이 나타났고, 이를 완화한 v2에서는 학습 효과도 함께 약해지는 문제가 발생했습니다.

#### 2. 하이퍼파라미터별 영향 분석 부족

QLoRA v1에서 v2로 변경하면서 LoRA rank, alpha, dropout, epoch, learning rate 및 target module을 동시에 조정했습니다.

과적합은 감소했지만 여러 설정을 한 번에 변경했기 때문에, 어떤 하이퍼파라미터가 결과에 가장 큰 영향을 주었는지 개별적으로 확인하지 못했습니다.

#### 3. 제한된 평가 범위

모델과 프롬프트의 조합을 유용성, 스타일 준수도, 응답 길이 및 추론 속도로 평가했지만, 제한된 테스트 사례를 대상으로 진행한 자체 정성평가라는 한계가 있습니다.

향후에는 테스트 질문 수와 평가 인원을 늘리고, 문체 일관성 및 외래 문자 혼입률 등 객관적으로 확인할 수 있는 평가 기준을 추가할 필요가 있습니다.

#### 4. Fine-tuned 모델의 성능 한계

최종 평가에서 Fine-tuned 모델 + 강한 프롬프트는 유용성에서 가장 높은 4.5점을 기록했지만, 종합 평점은 4.13점으로 Base 모델 + 강한 프롬프트의 4.30점보다 낮았습니다.

작은 데이터셋을 사용한 파인튜닝만으로는 Base model의 일반적인 한국어 생성 능력을 안정적으로 넘어서는 데 한계가 있었습니다.

### 개선 방향

- 소설의 감정과 분위기를 다양하게 표현하는 고품질 데이터 추가
- 학습 데이터의 중복 표현과 외래 문자 사전 검수
- 소설 본문과 작가 코멘트의 학습 범위를 분리한 실험
- 한 번에 하나의 하이퍼파라미터만 변경하는 비교 실험
- 테스트 질문과 평가 인원을 확대한 정량·정성 평가
- Base 모델과 Fine-tuned 모델의 장기적인 출력 안정성 비교

### 회고

이번 프로젝트를 통해 파인튜닝을 적용한다고 해서 항상 Base model보다 좋은 결과가 나오는 것은 아니라는 점을 확인했습니다.

처음에는 학습 효과를 높이는 데 집중했지만, QLoRA v1의 과적합과 v2의 학습 효과 저하를 경험하면서 데이터 규모와 학습 강도 사이의 균형이 중요하다는 점을 배웠습니다.

또한 최종 평가에서 Base 모델 + 강한 프롬프트가 가장 높은 종합 점수를 기록하면서, 생성형 AI의 품질은 모델 학습뿐 아니라 구체적인 프롬프트 설계에도 크게 영향을 받는다는 점을 확인했습니다.

EXAONE 환경 호환성 분석부터 데이터셋 구축, QLoRA·bf16 LoRA 학습, 버전별 출력 비교 및 프롬프트 개선까지 직접 수행하며 모델 선택과 학습 방법을 실제 결과에 근거해 판단하는 경험을 쌓았습니다.

향후에는 더 많은 데이터를 학습시키는 것에만 집중하기보다, 데이터 품질과 평가 기준을 먼저 설계하고 한 번에 하나의 조건을 변경하는 체계적인 실험 과정을 적용하고 싶습니다.
